Radius, by rule

The left shape is what the app has now. The right is what the rule gives. Four families, and only one number is ever chosen by hand.

1. Controls — the corner is a quarter of the height

44px tall text-input → text-input 12px → 11px
42px tall primary-button → primary-button 12px → 10.5px
42px tall ghost-button → ghost-button 12px → 10.5px
42px tall nav-tab → nav-tab 12px → 10.5px
36px tall small-button → small-button 10px → 9px
32px tall step-nav → step-nav 10px → 8px
28px tall segmented button → segmented button 8px → 7px

Nothing is typed but the height. border-radius: calc(var(--control-height) * 0.25) does the rest, so changing a button from 42px to 48px moves its corner with it.

2. Pills and dots — fully round, whatever the size

chipevent-factslot-buttonreward-band
the one that changesDVL→DVLtag-pill: 10px → round

The dots were drawn two ways before, 50% and 999px, for the same result. One idea now.

3. Panels — one fixed corner, because their height follows their contents

glass panelunchangednext-tileunchangedprofile-cardwas 16pxdialogwas 22px

A share of the height means nothing here, because the height is whatever fits inside. The dialog keeps square bottom corners only because it meets the edge of the screen.

4. Sized by one number — the corner is a share of it

60034px4.1px corner60044px5.3px corner60072px8.6px corner600110px13.2px corner

The reward tile and the fort card. Everything is a share of the one number, which is why the same tile reads inside a timeline and across a fort board. This was already right.
